# v0.2a artifact-first CTF triage worklog

> **Historical record — superseded in part.** The fixed browser fixture and its
> key flow described below were removed for the blank-workspace release. Use
> [the current operator guide](../usage-guide-vi.md) for supported commands.

## Objective

Add a safe first AI-assisted capability for all declared CTF categories without
turning a model response into autonomous execution or a solved claim.

## Delivered slice

- Category-neutral challenge taxonomy for 13 CTF disciplines and an offline
  `artifact_bundle` target.
- Explicit manifest `tool_profile` and `skill_profile` allowlists.
- Reviewed, digest-pinned category guidance. Selection is deny-by-default and
  does not load plugins or execute code.
- `artifacts.inspect`: bounded static fingerprinting through `ToolRuntime` with
  flag, bearer-token, and OpenAI-style-key redaction.
- OpenAI Responses adapter with one in-memory credential call, strict JSON
  schema, `store: false`, `tools: []`, timeout, and redacted diagnostics.
- `TriageOrchestrator`: disposable artifact workspace, static inventory and
  fingerprints, evidence-cited proposals only, `completed` terminal state, no
  action execution, no verification, no `solved` transition.
- Offline paired evaluator with suite/config/fixture/provenance commitments,
  blind-routing-only category accuracy, evidence citation quality, valid
  proposal rate, latency, and invalid output counts.
- Local stdio MCP gateway with two read-only tools only; every call is routed
  through `ToolRuntime`, bounded by manifest call and wall-time budgets, and
  operates on a disposable copy of declared artifacts.
- Manifest-first UI improvements that distinguish proposals/completed triage
  from verified results. The later local-browser amendment below adds only a
  fixed-fixture, one-shot provider boundary; it is not generic credential UI.

## Trust boundaries

1. The manifest is the category, artifact, tool, and scope authority.
2. The model sees only bounded/redacted context; it has no tool/native-tool
   access in this slice.
3. Facts, hypotheses, and suggested actions cite only evidence actually sent
   to the model; facts/hypotheses remain proposed/open until independently supported.
4. Suggested actions are stored as untrusted data and are not experiments.
5. Only the existing independent verifier can ever transition a run to solved.
6. CLI keys stay at the local CLI-to-provider boundary. The separate Compose
   browser demo accepts a one-use key only in an active request for a
   server-owned fixture; keys remain absent from manifests, traces, artifacts,
   browser storage, database state, and error diagnostics.

## Deliberate non-goals / next gates

- No generic category solver or untrusted code execution.
- No live provider test in CI; it requires explicit local opt-in and an
  operator-selected model.
- No claim that AI is stronger/faster/more accurate until a frozen reviewed
  paired suite produces those metrics.
- No HTTP/public MCP exposure; no host shell, network, archive extraction, or
  generated-code tool may be introduced through the local stdio facade.
- Full pwn/reverse/mobile/forensics execution needs a proven rootless sandbox,
  category packs, verifier profiles, and benchmark gates first.

## Browser live-demo amendment (2026-07-27)

- Added `POST /v1/demo/triage/openai`, enabled only by
  `CTFMESH_BROWSER_LIVE_TRIAGE_ENABLED` (Compose local profile only). It
  requires an allowed browser Origin, an explicit acknowledgement, strict
  body schema, a one-use `SecretStr` key, and a correlation-id replay window
  that stores only a successful `run_id`.
- The endpoint supplies its own static offline Crypto artifact and pins
  `gpt-4.1-mini`, a 900-token output cap, a timeout, `store: false`, and no
  provider-native tools. It rejects browser-selected artifacts, manifests,
  targets, models, endpoints, tools, or actions.
- The UI uses a password field outside browser storage, clears it after every
  submit, calls the same-origin API once, and labels the result as **Live
  OpenAI read-only triage** rather than Council/multi-provider behavior.
- Added provider payload, fixed-fixture, API deny-path/idempotency, and UI
  regression coverage. No real provider credential was used in automated
  verification.
