# v0.5 multi-provider archive-triage worklog

## Objective

Provide a local, one-shot UI boundary for an operator's OpenAI, Gemini, or
DeepSeek key while keeping third-party CTF skill/MCP sources declarative,
provenance-pinned, and outside the execution path.

## Delivered slice

- Added provider-neutral immutable triage contracts and three reviewed adapter
  paths: OpenAI Responses, Gemini's OpenAI-compatible endpoint, and DeepSeek
  Chat. The provider registry is code-owned; a browser request cannot supply a
  URL, header, retry policy, provider tool, or fallback provider.
- Added the Archive Receipt credential bay: provider selector, exact model ID,
  password field, explicit one-time egress acknowledgement, and status labels
  that distinguish target traffic from provider egress. The form clears its
  model/key/acknowledgement when the archive or provider changes and clears the
  key as a triage request starts. It does not use browser storage.
- Made the archive-to-provider boundary fail closed. Provider evidence now
  contains only generated file IDs, sizes, SHA-256 values, media types, and a
  controlled structural profile, including fixed CTF-topic markers
  (web/crypto/binary/network/forensics/encoding/sandbox). It never contains
  archive paths, source text, printable strings, raw bytes, direct-candidate
  values, or a model transcript.
  Local receipt redaction remains best-effort display/storage hygiene, not the
  security mechanism for egress.
- Required an explicit provider and `provider_egress_acknowledged: true` at the
  API boundary. Triage JSON is limited to 16 KiB and an API key to 8 KiB; the
  route rejects a missing/invalid/oversized `Content-Length` before JSON parsing.
- Allowed only one successful provider request per immutable receipt. Failed
  provider calls do not persist an AI result and may be retried with a fresh
  one-time key. A completed receipt rejects a second call before a backend
  request can occur.
- Mapped provider errors to a fixed public-code allowlist; unexpected adapter
  codes become `provider_failure`. Request cleanup clears the parsed
  `SecretStr` and never logs provider diagnostics.
- Sealed the OpenAI transport to `https://api.openai.com/v1/responses`, with
  redirects and ambient proxy trust disabled. Tests can inject only a low-level
  HTTP transport, not a different client origin.
- Exposed `GET /v1/archive-triage/providers` and `GET /v1/skill-catalog` for
  non-secret operator inspection. The catalog/profiles use source metadata
  pinned by commit, content digest, license digest, SPDX ID, and source role;
  they perform no runtime fetch/install/prompt injection or remote MCP setup.

## Assumptions and remaining risks

- No live provider call was made because no operator key/model was supplied.
  Provider account access, exact model availability, rate limits, and retention
  policy remain the operator's responsibility.
- Gemini's OpenAI-compatible surface and DeepSeek JSON mode receive local
  schema/evidence validation; they are not represented as strict-schema
  guarantees in the receipt.
- This is a local single-operator credential boundary, not a production secret
  broker, multi-user auth layer, or provider council/router.
- Source pins are review metadata, not executable trust. Updating a source or
  adding a remote MCP/provider requires a fresh security/license review,
  versioned contract, policy enforcement, and deny-path tests.
- Archive triage stays proposal-only and offline with respect to challenge
  targets. It does not execute code, start target networking, run an exploit,
  or independently verify a flag.
