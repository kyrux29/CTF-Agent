# CTFMesh Pi v0.1 — Milestone 1 worklog

**Status:** complete on 2026-08-28
**Canonical plan:** [CTFMesh-Pi-v0.1-ExecPlan.vi.md](../CTFMesh-Pi-v0.1-ExecPlan.vi.md)

## Scope completed

M1 implements a durable, non-model vertical slice. It proves the control-plane
state/evidence/verifier boundaries before Pi, a model, target access, or code
execution is introduced.

- Added strict, infrastructure-independent runtime contracts in
  `packages/domain`: sealed `ContextManifest`, evidence references, bounded
  context budget, task, preflight observation/artifact, clean replay, and
  verification-proof types. A worker task has no arbitrary context dictionary.
- Added forward-only Alembic migration `0002_runtime_kernel` and SQLAlchemy
  models for durable jobs, leases, branches, contexts, observations,
  idempotency records, budget ledger, and event outbox. SQLite and PostgreSQL
  install database-level `run_events` update/delete rejection triggers.
- Added repository operations with transactionally coupled event/outbox writes,
  idempotent product run start, compare-and-swap leases, task completion,
  atomic budget debit, and proof-artifact checks before `solved`.
- Added deterministic read-only preflight. It emits archive declaration, file
  inventory, extension histogram, route/dependency heuristics, and bounded
  redacted snippets as immutable observation artifacts. Trusted source roots
  are injected by composition; the browser/API cannot provide host paths.
- Added `RunEngine` and a deliberately test/dev-only `FakeRunHarness`. The
  harness proves `PREPARING → RUNNING → VERIFYING → SOLVED` with an opaque
  proof fixture and never invokes a model, tool, target, or raw flag.
- Changed `POST /v1/runs` to create a `PREPARING` run and enqueue preflight
  atomically through `RunEngine`. It accepts an optional safe
  `Idempotency-Key`; retrying identical input survives process restart.
- Added a durable preflight-failure outcome. Safe source/preflight errors mark
  only the leased job and active preparing run failed; no ambiguous operation is
  silently retried.
- Fixed manifest storage round-tripping for `artifact_bundle`: validated
  documents preserve declared fields rather than serializing empty default
  network fields that the contract correctly rejects.

## Security and product boundaries retained

- API requests only create durable work; they do not call the fake harness.
- No endpoint accepts a source root, raw tool input, verifier proof, or a
  direct `solved` transition.
- Events have payload redaction, hash-chain metadata, database append-only
  guards, and an outbox record inside the same transaction.
- An affirmative verification requires a same-run immutable artifact produced
  by `independent-verifier`, plus manifest-required clean replay results.
- The fake proof stores only digests/masked text. It never contains a raw flag.
- Redis and MinIO were removed from Compose because no source consumer exists;
  M1 uses PostgreSQL plus the existing local content-addressed artifact volume.

## Assumptions and remaining risks

- M1 intentionally has no production consumer for queued preflight jobs. Pi
  Runner/event bridge is the next milestone; source/HTTP tools remain deferred
  to M3.
- Full Compose startup was attempted after the cleanup but cannot complete in
  this execution environment: Docker could not resolve `files.pythonhosted.org`
  while downloading locked `greenlet==3.5.4` during API image build. This is an
  environment DNS/dependency-cache blocker, not a passing smoke result. The
  code-level full suite, migration, config, and web build gates above passed.
- PostgreSQL-specific `SKIP LOCKED` behavior and trigger execution still need a
  live PostgreSQL integration run once the Compose build can fetch its locked
  dependencies.
- No model/provider key, target endpoint, arbitrary shell/code execution, or
  challenge archive-to-source mounting was added in M1.

## Next prerequisite

M2 may start only with the current M1 tests preserved: Pi must run in an empty
trusted CWD with all built-in tools disabled, claim the durable job table, and
emit typed events. It must not receive target access, source mounts, API keys,
or a Docker socket.
