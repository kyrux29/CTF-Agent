# v0.3 Council demo worklog

> **Historical record — superseded.** The scripted Council launcher and its
> demo endpoint described below were removed for the blank-workspace release.
> Use [the current operator guide](../usage-guide-vi.md) instead.

## Outcome

Added a credential-free, evidence-first Council slice that can be launched from
the existing Docker Compose stack and viewed in Evidence Workbench.

The demo deliberately uses scripted profiles. It proves the orchestration
contract and policy boundaries without claiming to call or benchmark a hosted
model.

## Implemented slice

- Provider-neutral contracts in `ctfmesh_provider_base`:
  `ModelProfile`, `CouncilTask`, `CouncilClaim`, `CouncilCritique`,
  `CouncilDecision`, non-executable `CouncilProposal`, `CouncilCompletion`,
  validation, and a deterministic
  `ScriptedCouncilBackend`.
- `CouncilDemoOrchestrator` with two independent first-round branches, a
  falsifier, an adjudicator, append-only Council events, immutable evidence,
  and a proposal-only next step. The adjudicator task is created only after it
  receives the falsifier's complete critique set; rejected or unsupported
  claims cannot be selected.
- One real policy-gated `artifacts.inspect` invocation over a local artifact;
  no host shell, target request, generated-code execution, provider-native
  tool, or API key is used. The policy audit event is recorded before the
  handler enters, and the disposable workspace is removed after immutable
  artifacts are persisted.
- A repository-level hypothesis status transition so criticism can causally
  move an existing proposal to `supported`, `rejected`, or `suspended` without
  rewriting its original claim.
- `POST /v1/demo/council`, Council metadata in the console projection, and a
  UI card that makes the rejected branch and withheld execution visible.

## Assumptions and limits

- Compose continues to be the single local packaging entry point:
  `docker compose up --build --wait`.
- Council launch invokes a local deterministic endpoint only and never accepts
  a key. The separate, visibly labelled Live OpenAI gate added later is a
  one-shot fixed-fixture triage request, not part of the Council flow.
- Profile labels such as `simulated-gpt` and `simulated-gemini` are protocol
  fixtures, not provider calls or performance claims.
- Live Gemini/DeepSeek/xAI/Kimi/GLM adapters, a multi-provider secret broker,
  health-aware routing, and benchmark-based finalizer selection remain explicit
  future phases. They must be added behind the same contracts and policy gate
  rather than enabled by environment variables alone.
