# v0.4 archive-intake worklog

## Objective

Add a usable local path for an authorized CTF operator to upload one compressed
artifact bundle, obtain a bounded evidence receipt, optionally request
read-only AI triage, and inspect direct input candidates without falsely
claiming a verified solve.

## Delivered surface

- `POST /v1/archive-intakes` streams a raw archive body into an intake-owned
  staging directory. The browser uses `X-Archive-Name` only as display metadata;
  it never supplies a host path.
- Supported content-recognized formats are ZIP and standard-library TAR
  variants (`tar`, gzip, bzip2, xz). The route rejects unsupported/encrypted
  input, path traversal, Windows drive paths, backslashes, NUL/control paths,
  duplicate and file-prefix conflicts, links, special/sparse TAR members,
  oversized entries, over-count archives, ZIP compression-ratio bombs, and
  expanded-size violations.
- Extraction copies regular files chunk-by-chunk to a `0700` intake workspace
  with `O_EXCL`-style creation. Nested archives remain ordinary files.
- A public `report.json` contains only redacted display paths, hashes, media
  hints, static category hints, and candidate counts. A private local index is
  never exposed through an API route and exists only to reopen the operator's
  extracted files without putting raw filenames in the report.
- `POST /v1/archive-intakes/{id}/candidate-flags/reveal` rescans source files
  only after explicit confirmation. Raw values are returned to that response,
  marked `unverified_input_candidate`, and are never persisted in the report,
  event store, or provider prompt.
- `POST /v1/archive-intakes/{id}/triage` accepts an exact model ID and one
  in-memory OpenAI key after receipt creation. It builds redacted static
  evidence, uses the existing structured Responses adapter with `store: false`
  and no provider-native tools, validates evidence citations, and writes a
  proposal with `execution: none` and `verification: not_attempted`.
- The frontend exposes this as an archive receipt rail before the existing
  manifest Scope Ledger. The key is kept in React state only and cleared when
  triage begins. Nginx streams up to 128 MiB to the API instead of buffering a
  permitted upload in the read-only Web container.

The ZIP and TAR smoke inputs were temporary archives made from the repository's
public `LICENSE`, then removed. The volume reset removed their receipts and all
other runtime state before handoff.

The first broad Python test pass used a writable bind mount and left root-owned
Python/pytest cache files in the working tree. Subsequent checks use a read-only
source mount, disabled bytecode writing, and no pytest cache provider. Removing
the pre-existing root-owned caches requires the local user's sudo password; no
source or runtime product data is affected.

## Residual risks and deliberately absent behavior

- `zipfile` and `tarfile` still parse attacker-controlled bytes in the API
  process. Quotas limit disk/memory expansion, but Python thread cancellation
  cannot reliably interrupt a decompressor that consumes CPU. A production
  profile needs the planned rootless sandbox with CPU/RAM/time/pid and egress
  limits before arbitrary high-risk parser support is claimed.
- This is a receipt and proposal workflow, not an autonomous generic solver.
  It does not execute files, recurse archives, run generated code, contact a
  target, invoke MCP tools, or change any run to `solved`.
- Only OpenAI Responses is connected to the browser boundary in this phase.
  Multi-provider routing, secret brokering, category execution packs, and an
  independent verifier remain future work.
