# CTFMesh Pi v0.1 — Milestone 0 worklog

- Status: complete — acceptance gates passed on 2026-08-28.
- Canonical plan: [CTFMesh-Pi-v0.1-ExecPlan.vi.md](../CTFMesh-Pi-v0.1-ExecPlan.vi.md)

## Scope

Milestone 0 only locks the v0.1 boundary and proves the pre-existing verifier
authority invariant. It does not start the durable kernel, Pi Runner, Docker
slots, target tools, UI changes, or a live provider integration.

## Changes recorded so far

- Added the execution-plan companion and five ADRs for Pi, Docker socket,
  Web-only scope, verifier authority, and Hint Card epistemics.
- Linked `AGENTS.md` to the plan and added key/sandbox/resource-loader rules
  plus canonical lock and Compose validation commands.
- Extended ignore rules for generated caches, builds, local Pi sessions, and
  logs; no existing user files were deleted.
- Classified `CodexExecBackend` and `ScriptedCouncilBackend` as
  `legacy-dev-only`; they remain only for compatibility and deterministic
  contract tests.
- Added a deny-path regression that rejects a spoofed verifier actor from
  transitioning a run to `solved` directly.
- Removed the generated Web build output and the stale `.pytest_cache` and
  `.ruff_cache` directories after verification. Dependency installations were
  retained because they are ignored development prerequisites, not release
  artifacts.

The host did not expose `uv`, and the existing virtualenv uses a
container-relative `/workspace` interpreter path. To preserve a read-only
source checkout, the Python gates ran in the locally cached pinned Python 3.12
container mounted at `/workspace`; the Node binary was mounted read-only for
Pyright. Ruff and uv caches were redirected to a temporary directory and
deleted after the run. This is an execution-environment workaround, not a
product configuration change; the canonical CI commands remain those in
`AGENTS.md`.

## Assumptions and remaining risks

- This workspace has no `.git` directory, so the ExecPlan's `git status`
  cleanliness check cannot be executed here. No repository initialization or
  destructive cleanup will be performed merely to satisfy that check.
- The legacy classifications document and expose the migration boundary; a
  future Pi composition root must actively reject these backends before it is
  production-enabled.
- Milestone 1 is intentionally still unimplemented. Its durable kernel and
  fake vertical slice are the next permitted scope; Pi, target tools, and live
  model execution remain out of scope until then.
