# M5 worklog — verifier độc lập và ba local replay lab

**Hoàn thành implementation:** 2026-08-29
**Canonical plan:** [CTFMesh Pi v0.1 ExecPlan](../CTFMesh-Pi-v0.1-ExecPlan.vi.md)
**Hướng dẫn vận hành:** [M5 verifier và local labs](../operations/m5-verifier-labs.vi.md)

## Mục tiêu đã hoàn thành

M5 đóng một vertical slice xác minh độc lập cho **ba Web lab local do dự án sở
hữu**. Candidate không còn có thể dựa vào text tự báo của model: chỉ plan khai
báo canonical, evidence đã seal, hai replay sau hai reset khác nhau, và proof
opaque do controller ký mới có thể chuyển run từ `VERIFYING` sang `SOLVED`.

Đây là closed local regression/demo profile, không phải verifier generic cho URL,
archive, challenge instance hoặc payload tùy ý của operator. M3 authorized
source-slot/lab E2E vẫn là gate riêng đang mở.

## Thay đổi đã thực hiện

- Thêm domain contract closed-world `ExploitPlanV1`, draft/submission,
  replay/proof/completion. Plan chỉ cho `GET` target-relative, query/header
  allowlist, biến exact-placeholder, một flag capture cuối và reference evidence
  duy nhất; URL tuyệt đối, redirect, shell/script, raw flag và field lạ bị từ
  chối trước persistence.
- Bổ sung `verify` job kind, `ExploitCandidate`/`Verification` persistence,
  migration `0006_verifier_candidates`, candidate queue/lease/idempotency và
  immutable CAS namespaces `candidate-plans`/`verification-proofs`.
- Bind `web.path_traversal`, `web.authz_boundary`, `web.sqli_basic` vào đúng
  một profile target nội bộ bằng mapping code-owned ở DB/verifier. Manifest hay
  candidate không thể tái dùng technique để chọn service/origin khác.
- Thêm Pi `candidate.submit` parser/tool/ACL/prompt contract. Chỉ
  `exploit_builder` có capability đã policy-gate mới đi qua API internal; không
  có public endpoint nhận raw candidate, plan body hoặc flag.
- Thêm API public read-only projection `/v1/runs/{id}/candidates` và
  `/v1/runs/{id}/verifications`, cùng internal verifier lease/work/completion/
  failure routes dùng service token riêng. Public response không trả raw flag,
  candidate text hay plan body.
- Xây dựng `lab-controller`: mỗi reset sinh flag ngẫu nhiên vào đúng one named
  volume, target chỉ mount volume đó read-only. Controller chỉ trả reset metadata
  hoặc proof opaque; private Ed25519 seed chỉ có trong controller, verifier chỉ
  nhận public key để kiểm signature.
- Xây dựng verifier worker/replay driver: đọc immutable plan bounded, no proxy,
  no redirect, cookie jar mới cho từng attempt, reset/replay hai lần, chỉ giữ raw
  target candidate trong memory và trả proof/failure code không chứa raw flag.
  Outage không tự reject/solve: run giữ `VERIFYING` để lease/retry xử lý.
- Bổ sung migration `0007_controller_proof_context`: proof replay pass giờ lưu
  cả `controller_lab_id` và UTC `controller_issued_at` đã ký. Từ proof artifact
  bền, auditor có thể dựng lại chính xác payload Ed25519 và tái kiểm signature
  sau khi controller response/raw candidate không còn trong memory.
- Thêm ba service lab tối thiểu `web-path-traversal`, `web-authz-boundary` và
  `web-sqli-basic`; không có static flag/seed/answer trong source. Compose M5
  tách `verify-controller` và ba `verify-lab-*` bridge, không publish lab/API/
  verifier/controller port, không Docker socket/privileged/host network, và giữ
  Web ingress ở loopback. `WEB_PORT` cho phép smoke project song song mà không
  nới host bind. Initializer M5 chỉ `chown` đúng ba mount root (không recursive)
  để restart vẫn chạy được dưới capability tối thiểu sau khi controller đã tạo
  file `0444` trong volume.
- Cập nhật `.env.example`, README, operator guide, release-readiness và ExecPlan
  để mô tả chính xác profile M5, secret ownership và hạn chế generic verifier.

## Regression và deny-path coverage

- `test_m5_replay.py`: schema/plan malformed, URL/shell/host/variable/op không
  được phép; two reset/cookie jar sạch; target outage không solve.
- `test_m5_lab_controller.py`: flag rotate mỗi reset, API không leak flag,
  Ed25519 tamper/wrong public key fail, và POST reset thiếu controller token trả
  `401` mà không tạo flag volume.
- `test_m5_labs.py`: behavioral contract và full canonical-plan replay của cả
  ba lab, gồm reset hai lần, lowercase header contract cho authz, proof recheck
  và assertion không serialise raw flag.
- `test_m5_candidate_pipeline.py`: durable queue → verifier, two-replay happy
  path, text đúng/plan sai reject, outage giữ `VERIFYING`, và target rebinding bị
  từ chối.
- `test_m5_worker.py`, `test_m5_api_boundary.py`, `test_compose_m3.py`: missing
  public key/token, internal/public boundary, secret/network/mount hardening và
  loopback-only `WEB_PORT` override.

## Assumptions, boundaries và remaining risks

- M5 credentials are deployment secrets supplied at runtime. The controller
  private key, verifier/controller tokens and raw flags must never be committed,
  logged or added to browser/API request bodies.
- Verifier service token is a trusted internal boundary. API validates durable
  plan/proof bindings; verifier additionally verifies the controller's Ed25519
  proof before submitting completion. A deployment must protect the internal
  Compose network and secret injection path.
- The proof authenticates fresh replay against M5's own local labs. It does not
  establish that a third-party target is authorized, stable or solved; broadening
  this requires a future reviewed target/verifier profile, not a configurable
  URL field.
- M5 deliberately has no user-facing candidate authoring widget. Public UI/API
  may observe state safely; candidate submission remains a typed Pi-internal
  action after evidence/policy checks.
- Next work is to close M3 authorized source-slot/lab E2E, then M6 evaluation,
  chaos cases and release evidence. Do not claim model quality or generic solve
  ability from the M5 synthetic smoke.
