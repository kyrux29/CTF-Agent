# Blank-workspace cleanup worklog

> **Historical record — superseded in part by archive intake and M5.** The
> default-profile cleanup result (no bundled operator target or demo route)
> remains current. M5 later adds three opt-in synthetic local regression labs
> with random runtime flags, not an operator demo route. The statements below
> that browser artifact upload/key entry are absent describe the prior v0.3b
> surface; see `docs/usage-guide-vi.md` and the v0.4 archive-intake worklog for
> the current bounded, loopback-only receipt flow.

## Objective

Deliver CTFMesh as an empty local workspace. The repository and its Compose
image must not ship a runnable practice challenge, stored challenge state,
browser credential entry point, or fixed-fixture execution path.

## Changes

- Removed bundled lab assets, manifests, benchmark fixtures, demo routes, demo
  commands, scripted demo orchestration, and their runtime data paths.
- Replaced the browser launcher with the Scope Ledger: JSON manifest
  validation/import, an explicit empty state, and tracked-run records only.
- Kept user material under ignored, read-only-mounted `challenges/`.
- Removed obsolete onboarding/Council UI styles and neutralized the UI contract
  snapshot used only by frontend tests.
- Changed the default recorded provider to `operator-pending`; no UI action
  starts a model or target interaction.
- Added an API regression test proving each removed `/v1/demo/*` route is
  absent.
- Excluded tests, docs, historical assets, and the planning document from the
  API image context. Docker base images are digest-pinned for reproducible
  local rebuilds.
- Marked earlier demo worklogs and ADR as historical; the current operator
  guide is `docs/usage-guide-vi.md`.

## Verification performed

Commands and observed results:

```text
docker compose config --quiet
python3 -m compileall -q apps/api/src apps/cli/src packages services
docker compose up -d --build --wait
curl --fail http://127.0.0.1:8000/v1/ready
curl --fail http://127.0.0.1:8000/v1/challenges
curl --fail http://127.0.0.1:5173/healthz
```

- Compose built the API and web images and all services reached healthy state.
- A neutral `artifact_bundle` manifest was validated and imported through the
  live API; the list endpoint returned the persisted record.
- The three removed routes (`/v1/demo/run`, `/v1/demo/council`, and
  `/v1/demo/triage/openai`) returned `404`.
- The volumes were then reset with `docker compose down -v`, the stack was
  restarted, and `GET /v1/challenges` returned `{"items":[]}`.
- A headless-browser visual check confirmed the blank Scope Ledger and its
  visible “No challenge is loaded” state.
- The running API image was checked to confirm it does not contain
  `tests/`, `docs/`, `support/examples/`, `benchmarks/`, or the planning document.

## Remaining boundary at the time

The browser deliberately does not upload artifacts or accept provider keys.
Read-only OpenAI triage remains CLI-only and proposal-only. Generic execution,
verification, multi-provider routing, and secret brokering are not represented
as completed functionality.
