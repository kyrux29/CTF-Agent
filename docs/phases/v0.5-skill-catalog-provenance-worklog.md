# v0.5 skill catalog provenance worklog

## Objective

Add immutable provenance to the declarative CTF skill catalog without turning
an upstream skill repository or MCP server into executable runtime input.

## Delivered slice

- Added strict, frozen `SkillSourceRef` metadata: canonical HTTPS repository
  root, exact 40-character Git revision, safe repository-relative paths,
  content/license SHA-256 values, SPDX license, and explicit source role.
- Pinned the reviewed `ljagiello/ctf-skills` catalog at
  `d6662d26b5ed3caa56f5eaf6eb887964f3747162`, including README, license, and
  category-file hashes for AI/ML, crypto, forensics, misc, OSINT, pwn,
  reverse, and web reference metadata.
- Added reference-only pins for OWASP WSTG (web), pwn.college Dojo
  (pwn/reverse), and Google CTF (common). No upstream prose, code, fixtures,
  installer, or challenge content was copied into the repository or model
  prompt.
- Added `McpSourceProfile`: static category metadata locked to CTFMesh's local
  stdio read-only facade and exactly `artifacts_inspect` / `files_list`.
  Profiles cannot contain an endpoint, external connection, network access,
  code execution, or a broader runtime tool.
- Exposed catalog sources and local-only MCP profiles through
  `ctfmesh_skills`; no package performs I/O, plugin discovery, or MCP
  connection setup.

bytecode writes were disabled.

## Assumptions and remaining risks

- Source commit, README, and license hashes are static review inputs, not a
  claim that any upstream content is safe to execute or automatically inject.
- Updating a pin requires a human license/security review and a new digest;
  tags, branches, URLs from manifests, and runtime fetching remain unsupported.
- These profiles do not add remote/black-box tooling. Any future HTTP, sandbox,
  or external MCP integration must be a typed ToolRuntime capability with its
  own policy, scope, budget, and deny-path tests.
- `malware` and writeup/discovery workflows remain outside this slice because
  they need category/domain contracts or a separate post-triage lifecycle.
