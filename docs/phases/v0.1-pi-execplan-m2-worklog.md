## Completed so far

- Added isolated `services/pi-runner` with the exact locked
  `@earendil-works/pi-coding-agent` 0.84.3 dependency and upstream provenance.
- Constructed Pi directly through its SDK with an empty trusted CWD, in-memory
  settings, discovery overrides, `noTools: "all"`, role-specific custom tools,
  and an opaque JSONL store key on a dedicated named volume.
- Added typed, authenticated internal claim/work/reservation/event/completion
  APIs. Pi Runner has no database connection, challenge mount, target address,
  Docker socket or shell capability.
- Added durable session/steer lifecycle rows and forward migration `0003`.
  The master can delegate only through kernel validation; workers can only
  submit bounded evidence-backed findings. Neither can set `solved`.
- Added safe event bridging, secret redaction, restart-safe session identity,
  and fixture drivers that make no provider/model/target request.
- Corrected an upstream SDK semantic found by the restart test: its
  `deliverAs: "nextTurn"` queue is in-memory. M2 now creates the private
  transcript header atomically and appends idle-boundary steering directly to
  the durable session before acknowledging it. Symlink session stores are
  rejected.
- Added `pi-smoke` Compose profile plus a deterministic preflight worker and
  operator instructions in
  [docs/operations/pi-runner-m2-smoke.vi.md](../operations/pi-runner-m2-smoke.vi.md).
- Found and fixed a real Docker lifecycle defect: Compose invoked
  `python -m ctfmesh_orchestrator.worker`, but the module never called `main()`.
  The package now exposes `ctfmesh-preflight-worker`; Compose uses that console
  entrypoint and a subprocess regression proves an invalid configuration exits
  fail-closed rather than silently exiting 0.
- Updated the README and Vietnamese operator guide so the default no-consumer
  stack is not confused with the target-free M2 fixture profile.

## Security decisions and non-goals

- M2 is intentionally target-free. It does not mount challenge data into Pi,
  expose source/HTTP/browser/shell/generated-code tools, or perform direct
  provider egress.
- The Compose smoke uses `fixture`, not a fabricated flag/model result. A run
  remains unverified and cannot become `solved` without the independent
  verifier path.
- Operator steering is refused if it resembles a raw flag, bearer token or API
  key. Public events retain IDs/digests, not transcript text.
- Full live-model smoke is deliberately not claimed: M3 must first add the
  reviewed provider proxy, credential injection boundary and egress tests.
