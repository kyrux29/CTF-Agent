# M4 worklog — master/worker scheduler và Hint Deck

**Hoàn thành:** 2026-08-29
**Canonical plan:** [CTFMesh Pi v0.1 ExecPlan](../CTFMesh-Pi-v0.1-ExecPlan.vi.md)

## Mục tiêu đã hoàn thành

M4 thêm lớp autonomy có giới hạn cho scope Web CTF v0.1: một master chỉ điều
phối, tối đa hai worker branch hoạt động, và Hint Card của operator luôn là một
giả thuyết chưa được xác minh. Không thay đổi authority của verifier: không có
nhánh, finding, note hay self-report nào có thể chuyển run sang `solved`.

## Thay đổi đã thực hiện

- Thêm domain contracts chặt chẽ cho `HintTemplate`, `HintCard`, lifecycle,
  branch score factors và prompt-contract metadata. Note tối đa 500 ký tự;
  raw flag, bearer token và `sk-…` bị từ chối ngay ở boundary.
- Thêm catalog bất biến gồm ba template Web đã review: path traversal,
  authorization boundary và input-to-query. Catalog, role pack selection và
  score đều là policy thuần, không gọi model, database hay target.
- Persist scheduler metadata, fingerprint attempt và Hint Card trong migration
  `0005_hint_scheduler`. Scheduler áp dụng công thức score versioned, cap hai
  worker branch, role diversity, chống fingerprint trùng, stall sau hai turn
  rỗng và fallback deterministic từ catalog.
- Finding đối nghịch hoặc finding confidence cao chỉ tạo tối đa một falsifier
  có context evidence đã seal; không tạo council/chat worker. Falsifier có
  union các schema source/HTTP đã review để kiểm chứng độc lập, nhưng không có
  shell, code execution, candidate, verifier hay state-transition authority.
- Hint Card chỉ tạo branch/task theo template cố định. Note không nằm trong
  system prompt, context manifest hoặc event payload; Pi chỉ thấy note qua
  `state.get` dưới dạng operator data chưa tin cậy và phải kiểm chứng bằng tool.
- `avoid` là policy gate tại scheduler và tool gateway: chặn task mới và chặn
  cả tool call của task đã lease, đồng thời giữ event audit.
- Hoàn thiện lifecycle pause/resume/cancel. Cancel loại queued work mới, revoke
  turn đang chạy, enqueue abort Pi session và giữ nguyên events/evidence.
- Thêm API Hint Template/Card với request body strict, idempotency bắt buộc và
  lỗi chung không echo note. Projection console chỉ publish identifier-safe
  references và digest note.
- Xây dựng Hint Deck React có trạng thái lifecycle, filter metadata an toàn,
  impact preview, event timeline, evidence links, create/edit/dismiss controls,
  responsive layout và thông báo accessible. Filter không đọc hay gửi note để
  quyết định hiển thị.
- Cập nhật Pi reviewed role prompts/skill packs cho ba technique; mỗi role gửi
  version/digest prompt contract vào event session-start.

## Regression và security coverage

`tests/unit/test_m4_scheduler.py` kiểm tra policy/catalog/score, note không
thành prompt data, `avoid` chặn task/tool, xung đột tạo falsifier, fingerprint
trùng bị từ chối, stall fallback và cancel audit. API test kiểm tra catalog,
idempotency bắt buộc và lỗi note có flag không phản chiếu secret. Pi test kiểm
tra ACL worker/falsifier và prompt-contract event; Web test render Hint Deck,
lifecycle/event/evidence link và filter UX.

## Giới hạn còn lại và handoff

- M4 không giả lập một challenge, flag, provider response hay verifier proof.
  Stack Docker được giữ ở blank state để operator tự thêm challenge hợp lệ.
- M3 vẫn giữ trạng thái `in progress`: cần source-slot + authorized lab E2E do
  operator cung cấp. M4 không dùng kết quả tự báo của model để đóng gate này.
- M5 đã được hoàn thành ở phase sau với lab controller, declarative
  `ExploitPlan` replay hai lần và verifier-only `solved` cho three-lab local
  profile; M4 finding/hint vẫn chỉ là hypothesis/evidence, không phải kết quả
  solve. Xem [M5 worklog](v0.1-pi-execplan-m5-worklog.md).
- Secret detector ở Hint Card là deny-path rõ ràng, không phải DLP toàn diện.
  Operator vẫn không nên nhập credentials hoặc flag vào note.
