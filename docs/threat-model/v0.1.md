# Local operator threat model

## Trust boundary

```text
browser / CLI → loopback Control API → local event + projection store
                                  → bounded archive-intake volume
                                  → declared artifact workspace (CLI only)
                                  → typed policy/runtime contracts
                                  → one fixed provider adapter (optional)
```

The Web UI can stream one supported archive into an offline receipt. It does
not read host paths, execute archive content, contact a target, or execute
model-proposed actions. It may accept one selected provider key only after
receipt creation. For the explicit local single-operator profile, Settings
stores its provider-key map as plaintext in that browser origin's
`localStorage` (ADR 0011); it restores only in the same browser profile. The
selected key is passed to one fixed provider call with metadata-only static
evidence. The server requires an explicit provider and one-time egress
acknowledgement; a receipt accepts only one successful provider call. The
browser cannot choose a base URL, headers, arbitrary provider ID, or automatic
fallback. CLI live triage continues to receive its key only in the active
shell/call stack and works over manifest-declared artifacts.

## Assets to protect

- provider keys, cookies, bearer tokens, raw flags and challenge-private data;
- exact target scope and contest constraints;
- artifact integrity and provenance;
- ordered event history and verifier state;
- local Compose database/artifact volumes.

## Key controls

| Threat | Control |
|---|---|
| Browser credential leak | Provider keys may persist as plaintext only in the same protected loopback browser profile's `localStorage` under ADR 0011. This convenience store does not protect a compromised browser profile; keys are excluded from reports, DB, events, artifacts, errors, challenge mounts, sandbox, and API persistence. |
| Credential exfiltration / provider SSRF | The UI and request schema accept only three reviewed provider IDs. Each adapter fixes its HTTPS host/path, disables redirects and ambient proxy trust, has no retry policy or tools, and bounds response bytes. |
| Archive data egress | Provider evidence is fail-closed metadata only: generated file IDs, sizes, SHA-256 values, media types, and controlled structural markers. Archive paths, source excerpts, printable strings, and candidate values never leave through this route. |
| Upstream skill/MCP supply chain | Third-party references are checked-in metadata pinned by commit, content/license SHA-256, SPDX license, and role. Runtime never fetches or executes them; only CTFMesh-reviewed local guidance can reach a model. |
| Archive traversal/bomb/link | Raw streaming cap plus ZIP/TAR format detection, path canonicalization, link/special-file denial, duplicate/prefix conflict checks, per-entry/aggregate/ratio gates, and actual-byte copy enforcement. |
| Unscoped host-file read | Browser never supplies a host path; CLI materializes only declared relative paths into a disposable workspace. |
| Target expansion | `ChallengeManifest` validates exact allowed endpoints and contest restrictions. |
| Model-driven side effect | Triage is proposal-only; no model output is routed directly to a tool or verifier. |
| Sensitive data in UI/export | Intake reports apply best-effort redaction for raw flags/common secrets; provider evidence is separately metadata-only. Raw direct candidates and verified raw flags may be displayed only after explicit local reveal and are never persisted in the report/event store. |
| Event rewriting | Repository exposes append-only event paths and per-run sequence/idempotency controls. |
| Local service exposure | Compose publishes API/Web on loopback only; no Docker socket or privileged container is mounted. |

## Explicit non-goals

- multi-user authentication, tenant isolation, shared/server secret broker, audit retention,
  production ingress, and operational monitoring;
- generated-code execution, shell access, host Docker access, public MCP, or
  unrestricted network tooling;
- arbitrary parser/plugin execution, recursive archive extraction, or a general
  browser credential broker, remote MCP connector, or dynamic skill installer;
- proof that a model has solved a challenge without an independent verifier.

## Operator actions on incident

1. Stop the Compose stack: `docker compose down --remove-orphans`.
2. Revoke any provider credential exposed outside the intended shell.
3. Preserve/export needed local evidence before destructive reset.
4. Reset only if appropriate: `docker compose down -v`.
5. Review the manifest scope, local artifact permissions, and shell history
   before re-running triage.
